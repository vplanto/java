# 🚀 Roadmap: Java Course & Exam Evolution 2026

## 1. Методологія: Розширення "Stream API & Functional Thinking"
*Проблема:* Студенти сприймають Stream API як "складну магію", а не як базовий інструмент.
* **Action Plan:**
    * **Впровадити блок "Imperative vs Declarative":** Показати на пальцях різницю між `for-loop` та `stream()`.
    * **Візуалізація Lazy Evaluation:** Розробити діаграми, що показують, як дані течуть через пайплайн і чому вони "стоять" без термінального методу.
    * **Common Pitfalls:** Окремий урок про типові помилки джуніорів:
        - Debugging Streams (peek).
        - Reuse stream issue (IllegalStateException).
        - Side-effects in lambda (чому не можна міняти зовнішні змінні).

## 2. Інструментарій: "Exam Ticket Generator" (Automation)
*Проблема:* Поточний HTML — це клієнтський рандомайзер. Потрібен інструмент для генерації стабільних білетів для друку або PDF-експорту.
* **Technical Spec:**
    * **Input:** Markdown файл з базою питань (поточний формат).
    * **Logic:**
        - Алгоритм "Fair Shuffle": гарантувати, що питання не повторюються у сусідніх білетах.
        - Генерація N унікальних варіантів (наприклад, 30 унікальних PDF/HTML файлів).
    * **Stack:** Python script або Go CLI (для швидкості та простоти запуску).
    * **Feature:** Експорт у "Teacher Mode" (з відповідями) та "Student Mode" (без відповідей).

## 3. Аналітика: Feedback Loop & Data-Driven Adjustments
*Проблема:* Ми не знаємо, які питання "валять" студентів через погане формулювання, а які — через незнання.
* **Process:**
    * **Збір метрик:** Після екзамену зібрати статистику: на які питання було найбільше неправильних відповідей.
    * **Review:**
        - Якщо 80% групи валить питання — перефразувати питання або покращити лекцію.
        - Якщо питання проходять всі — воно занадто легке, замінити на складніше.
    * **Student Feedback:** Обробити текстові відгуки про зрозумілість формулювань.

## 4. Scrum Workshop Evolution: Від фейкового проєкту (VARTA) до реальних продуктів (Real PO + Agentic Pipeline)
* **Ідея:** Замість суто теоретичної симуляції Scrum на фейковому надскладному проєкті (`VARTA`), де код не доводиться до реального використання, дати командам (сквадам) **пул реальних прикладних проєктів на вибір**, де викладач виступає справжнім Замовником (Product Owner), який реально використовуватиме готовий продукт.
* **Робочий процес (Design First → AI CodeGen → Testing):**
    1. **Проєктування (Scrum ролі SME, UX, Architect):** збір вимог у PO, опис доменних правил (`DR`), граничних випадків (`EC`), User Flows (`UF`), бази даних та OpenAPI-контрактів до написання коду.
    2. **Генерація коду (DEV + Agentic Pipeline):** генерація Spring Boot сервісу та UI за допомогою AI суворо за затвердженою архітектурою та контрактами.
    3. **Тестування та поставка (QA + OPS):** покриття автотестами (Unit, `@DataJpaTest`, `MockMvc`, `Testcontainers`), пакування в `Docker Compose` та реальне приймання продукту Замовником на Sprint Review.
* **Пул проєктів на вибір командам (Catalog of Real Projects):**
    * **Варіант А (Фаворит 1) — «Home SE & Family Issue Hub»:** Бекенд та висококонтрастний дашборд (у стилі TRMNL) для настінного планшета біля входу + сімейний трекер задач із Telegram-ботом, попап-підтвердженням важливих подій (`Accept`) та агрегацією стану енергосистеми (графік ДТЕК, СЕС/АКБ, генератор, AQI, тривоги).
    * **Варіант Б (Фаворит 2) — «Genealogy Book & Archive Tracker»:** Локальний веб-сервіс (Spring Boot + PostgreSQL у Docker) для ведення родинного дерева, обліку вже переглянутих метричних книг та архівних справ (включно з порожніми результатами та номерами сторінок, щоб не гортати повторно через пів року), каталогу сканів та пошуку зв'язків свідків/хрещених (`Witness Network`).
    * **Варіант В (Можливо) — «LMS Git/Linux State Grader & AI Tutor»:** Сервіс для перевірки студентських практичних робіт, який оцінює фінальний стан Git-репозиторію або Linux-контейнера (а не історію введених команд) та надає AI-підказки в режимі ментора без видачі готового коду.
    * **Варіант Г (Цікаво) — «Config & Benchmark Comparator»:** Інженерний Docker-інструмент для збереження снапшотів конфігурацій (K8s/JVM) або результатів навантажувальних тестів/профайлінгу, автоматичного порівняння (Diff: Baseline vs Issue) та валідації за правилами («Rules of Play»).
